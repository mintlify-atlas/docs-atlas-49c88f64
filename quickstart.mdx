---
title: "Quickstart: Build and Run Your First Application"
description: "Clone the AIGLASS_DEV_ENV workspace, install the ARM cross-compilation toolchain, and deploy a Hello World binary to your device over ADB in minutes."
---

This guide walks you through setting up a cross-compilation environment on your host machine, writing a minimal C program, and running it on your AI Smart Glasses device. By the end, you will have a working binary deployed and executing on-device — the foundation for every application you build from here.

<Note>
  The build toolchain relies on `apt-get` and is supported on **Ubuntu and Debian only**, including Ubuntu/Debian running inside WSL2 on Windows. Other Linux distributions are not supported by `setup_build_env.sh`.
</Note>

<Steps>
  <Step title="Clone the development environment">
    All toolchain configuration and build scripts live in the `AIGLASS_DEV_ENV` repository. Clone it and enter the workspace root:

    ```bash
    git clone https://github.com/makevary/AIGLASS_DEV_ENV.git
    cd AIGLASS_DEV_ENV
    ```
  </Step>

  <Step title="Install build dependencies">
    Run the setup script to enable the `i386` architecture, update your `apt` index, and install all required build tools — including `texinfo`, `gperf`, multilib packages, `flex`, `bison`, and `cmake`:

    ```bash
    ./setup_build_env.sh
    ```

    Verify that the core tools are available after the script completes:

    ```bash
    cmake --version
    bison --version
    flex --version
    arm-rockchip831-linux-uclibcgnueabihf-gcc --version
    ```
  </Step>

  <Step title="Build the firmware">
    Choose the build variant that matches your hardware:

    ```bash
    # Device with display capability (DisplayVersion)
    ./build.sh

    # Device without display capability (AudioVersion)
    ./build.sh --without-display
    ```

    The `--without-display` flag disables the display launcher at startup (`skip S60_app_launcher`). If you are unsure, check whether your device has the optional JBD monocular display module.

    Confirm the output image was produced:

    ```bash
    ls -lh output/image/update.img
    ```
  </Step>

  <Step title="Connect your device via ADB">
    Connect the device to your host machine with a USB cable. Verify ADB can see it:

    ```bash
    adb devices
    ```

    You should see your device listed with a serial number and `device` status. If the device shows as `unauthorized`, check the on-device prompt to authorize the connection. If ADB is unresponsive, restart the server:

    ```bash
    adb kill-server
    adb start-server
    adb devices
    ```
  </Step>

  <Step title="Write the Hello World program">
    Create a working directory inside the `AIGLASS_DEV_ENV` workspace and write the source file:

    ```bash
    mkdir -p workspace/hello_world
    cd workspace/hello_world
    ```

    Create `hello.c` with the following content:

    ```c
    #include <stdio.h>

    int main(void) {
        printf("Hello from AI Smart Glasses!\n");
        return 0;
    }
    ```
  </Step>

  <Step title="Cross-compile for ARM Cortex-A7">
    Compile the source file using the ARM cross-compiler that was installed by `setup_build_env.sh`:

    ```bash
    arm-rockchip831-linux-uclibcgnueabihf-gcc -O2 -o hello hello.c
    ```

    Confirm the binary targets ARM:

    ```bash
    file hello
    ```

    The output should identify the binary as an ARM ELF executable linked for the device's uClibc runtime.
  </Step>

  <Step title="Push and run on the device">
    Copy the binary to the device's persistent storage and execute it:

    ```bash
    adb push hello /userdata/apps/hello
    adb shell "chmod +x /userdata/apps/hello && /userdata/apps/hello"
    ```

    Expected output:

    ```text
    Hello from AI Smart Glasses!
    ```

    Your binary is now running on the device. Use `adb shell` interactively to explore the filesystem, inspect running processes with `top`, or read logs.
  </Step>
</Steps>

<Warning>
  The device supports **2.4GHz WiFi only** (802.11b/g/n). 5GHz and 5G networks are not supported. When provisioning WiFi, make sure you are connecting to a 2.4GHz network.
</Warning>
